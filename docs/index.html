Measurement report Correction July 2026

I said the redundancy thesis was wrong.
I was measuring the wrong thing.

Berkeley's EPIC Lab reported that when several AI agents attempt the same task, only 10–20% of query sub-plans are distinct — a large prize in shared computation. I built the tracing, ran six conditions, and published that it didn't reproduce. Then I read the paper properly and ran the actual experiment. It reproduces at 17.7%. The error was mine, and where it came from is the interesting part.

Both readings are true at the same time, and that is the whole finding. Eight agents asked one question fifty-five different ways — but underneath, they scanned the same table with the same thirteen predicates computing the same ten measures. The repetition sits entirely below the level of the query, which is exactly why counting queries could not see it.

How I got it wrong

The published measurement is specific: the BIRD text-to-SQL benchmark, 50 independent attempts per task, redundancy defined as “the proportion of distinct sub-expressions relative to total sub-expressions across multiple agent attempts.”

Everything I ran differed on both axes at once.

 The published claimWhat I measured
SetupN agents, same taskagents on different questions
Unitsub-expressions in the planwhole queries
Verdict10–20% distinct“42.9%, doesn't reproduce”

Three failures, compounding. I worked from a summary rather than the source — the blog post says “sub-plans” and I operationalised it as “queries.” I dropped the setup entirely: I wrote a script whose whole design was eight agents on eight different questions, and reported its result as evidence against a claim about one task. Then a plausible story hardened. Once the first run came back efficient, “agents aren't wasteful” became the frame, and five further conditions were designed to test that rather than to reproduce the original.

The authors' claim survives a frontier model, a different schema, and a much smaller sample than theirs. That is a stronger result for them than it looks.

Why the unit changes the engineering

At 92.7% distinct whole queries, a cache keyed on the query text hits essentially nothing. That is the layer every data warehouse and every LLM gateway actually ships — Redshift result caching, Snowflake result reuse, prompt-level semantic caches.

So the prize is real and it is unreachable by the mechanism most people would reach for first. Capturing it needs multi-query optimization, shared scans and partial-result reuse — which is precisely what the paper proposes, and precisely what I spent six conditions arguing was unnecessary.

This also reconciles a result that looked contradictory. Real human and pipeline warehouse traffic — 18.9M production Redshift queries via Redset — repeats whole queries at 91.3% median. Agents repeat fragments. Both are redundant; they need entirely different machinery.

What still stands

These were measured correctly. They concern agents on different questions, so they neither support nor undercut the same-task claim.

  • Agents on different questions share little. Eight concurrent sessions on overlapping-but-distinct questions: 13% cross-session redundancy at whole-query level. A delegating coordinator: 9.1%.
  • Agents waste little. 34 of 41 results reached the answer, verified by matching result values against the answer text rather than trusting the agent's own claim.
  • Weak models don't fan out. Haiku 4.5 issued 5 queries to Opus 5's 6 on an identical question.
  • “You're paying a warehouse to watch an LLM think” was an n=1 artifact. 96.7% of a lone agent's bill is idle; with eight agents sharing a warehouse it falls to 23.7%.

Ten errors, and what they have in common

Most failed silently — code that reported healthy while doing nothing. Four moved a headline number in the direction I wanted.

Measured the wrong unit, then published a refutation Whole queries instead of sub-expressions; different questions instead of the same task. the finding inverted once corrected
A preflight that tested a different code path than production It wrote its own literal query tag and reported “✓ round-trips into query history” while every real agent query was being tagged ?. a check that doesn't exercise the real path is worse than no check
ALTER SESSION SET QUERY_TAG = ? does not bind in Snowflake It set the tag to the literal string "?" and returned success. Queries ran, IDs were captured, and every trace lookup found nothing. an entire agent run produced untraceable queries, with no error anywhere
Named the subagent tool Task when it is Agent Unknown tool names don't error, so the coordinator condition ran with delegation silently disabled and looked like a perfectly valid trace. an entire experimental condition was invalid
Regex-“parsed” SQL, then divided by the wrong denominator Couldn't read GROUP BY 1, 2 or date_trunc(); counted unmodellable queries as successfully deduplicated. 51% dedup → 20% against servable queries
A read-only guard that only inspected the start of the string select 1; drop table x passed it, and the driver executes multi-statement strings. verified against a canary table — it was dropped

The pattern is the transferable part. A measurement tool fails differently from a product: it returns a number either way, and a number is convincing. Four of these flattered the result, and the biggest one survived six experiments because each new condition was designed to confirm the frame rather than test the original claim.

Sub-expressions are approximated from the query shape rather than decomposed from a real execution plan — the direction is solid, the exact percentage is not authoritative.
